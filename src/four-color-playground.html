What is being timed?
  • Both demo methods receive identical region adjacencies, with a deterministic seed and map fingerprint. Maps are jittered square-grid Voronoi examples, not a representative collection of all planar graphs.
  • Each CPU worker runs Rust compiled to WebAssembly in private memory. Variant zero preserves the original search order; other workers use deterministic alternative orders. The first valid coloring cancels the other workers. Baseline and prototype trials run one at a time and alternate order.
  • Times measure wall-clock latency, including dispatch, result transfer, winner checking, progress handling, and cancellation requests. Worker creation, compilation, graph import, warm-up, and final drawing are excluded. Every worker shares one 100-second trial deadline. Counters describe the winning worker; partial maps show one active worker, never a merged coloring.
  • Additional workers vary the order of RSST reductions, or DSATUR tie-breaking when that diagnostic is selected. Speedups can come from a better search order; they are not a pure measure of CPU scaling. One worker preserves the original ordering. JSON includes the winning worker's kernel time separately.
  • Live maps show partial search states. Colored counts can decrease during backtracking and do not estimate time remaining. A completed coloring is marked Checked only after every shared border passes validation.
  • RSST uses the 633 original configurations, contractions, consistent boundary-color sets, and short-circuit reconstruction. Its small extension searches stay inside a configuration; it never falls back to whole-map DSATUR. The prototype removes independent batches of vertices with at most four remaining neighbors, runs DSATUR on any leftover core, and restores using complete Kempe-component swaps.
  • The prototype does not implement the full catalogue, discharging, separator recursion, or certified rank scheduler of the 2026 paper. It has no near-linear runtime guarantee. The RSST variant uses an exhaustive configuration/short-circuit locator in place of the paper’s linear discharging locator. It has no certified quadratic runtime and is not a formal proof of the Rust code.
  • The authors’ proof checker verifies all 633 configurations and all five unavoidability certificates. Those offline checks are separate from the map-coloring timings. RSST trials can report a resource limit (bounded graph storage or recursion) before the 100-second deadline; incomplete trials never count as successful timings.

A surprisingly simple rule.

The four color theorem says that any flat map of connected regions can be colored with at most four colors, so regions sharing a border have different colors. A corner touching another corner doesn’t count as a shared border.

“Peek at the connections” turns regions into dots and shared borders into lines. Coloring the map and coloring those dots are the same puzzle. A successful example is a demonstration, not a proof for every map.

About the paper and this exhibit

The reviewed paper proposes removing suitable regions, coloring a smaller graph, and restoring the removed regions with coordinated recoloring. This public exhibit uses a small search solver to demonstrate map coloring. The complete paper algorithm and its remaining formal verification are separate work.
